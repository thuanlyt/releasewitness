The smaller boundary

Runtime executes.
RelWit verifies.

The recommended architecture leaves planning, model routing, subagents and worktrees to Claude Code, Codex or another runtime. ReleaseWitness keeps only the provider-neutral assurance boundary around QA evidence and release-source identity.

Layers

01Native coding runtime

Claude Code, Codex or another tool owns planning, model routing, implementation, review agents and worktrees.

02Source-bound QA

relwit qa runs configured checks and fingerprints release-source bytes, executable bits, symlink targets and QA configuration.

03Deterministic gate

relwit gate exits non-zero when the recorded passing QA no longer applies to the current source; --require-clean also requires a clean Git tree.

04Bounded evidence

Durable summaries stay sanitized and inspectable; raw diagnostics remain local. Deployment authority stays outside RelWit.

Deprecated compatibility layer

DAG planning, mailboxes, runner bridge, supervisor cycles, checkpoints, knowledge-ledger skills and usage telemetry remain in the branch for compatibility, but ADR-0011 recommends deprecating and eventually deleting them. The 56-session study found no correctness or recovery benefit over native Claude orchestration.

The recommended protocol

coding runtime
plan → implement → review
        ↓
    relwit qa
        ↓
relwit gate --require-clean
        ↓
owner-controlled release

The runtime owns coding judgment. RelWit owns a narrow deterministic question: does the passing QA record still match the source being released?

Production gate

A task is not production-ready because a worker says “completed”. The supervisor needs acceptance evidence, passing checks, no open critical review finding and operational/rollback notes. Deployment remains an explicit user-authorized action.

Design principle

Filesystem automation can create durable work; it must not silently launch arbitrary models, change secrets or deploy a product.

Tóm tắt bằng tiếng Việt

ReleaseWitness dùng knowledge ledger, registry JSON, mailbox Markdown và supervisor cycle hữu hạn. Worker chỉ sửa scope đã claim; report phải có file, lệnh kiểm tra, evidence và blocker. Supervisor review/QA trước khi đóng task.
